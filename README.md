# 足し算パズル

合計がお題の数になるように、盤面の数字を繋げて消す。90秒でどれだけ消せるかを競う暇つぶし用パズル。
仕様は [spec.md](spec.md) にある。

ブラウザで動く PWA。ビルド無しの素の ES モジュールで書いてあるので、このディレクトリをそのまま静的配信すれば動く。

## 動かす

```sh
npm start     # http://localhost:8080
npm test      # ゲームロジックのテスト
npm run icons # icons/*.png を作り直す
```

スマホで遊ぶときは、同じネットワークから `http://<PCのIP>:8080` を開いてホーム画面に追加する。
Service Worker は `https` か `localhost` でしか登録されない（無くても遊べる）。

## 記録の保存先

自己ベストは端末のローカルストレージに置いているが、**iOS はホーム画面からアプリを削除すると、
そのアプリの保存領域ごと消える**。これは web 側からは防げない。なので端末の外にも預ける。

預け先は Cloudflare Workers + KV（`worker/index.js`）。プレイヤーは何もしなくてよい。

- 起動時に取りに行き、端末の記録と合わせる（お題ごとに高い方を採る）
- セッションが終わって記録が伸びたら送る
- 通信できなくても遊べる。送りそびれたら覚えておいて、次の起動で送り直す
- `src/app/sync-config.js` の `SYNC_URL` が空なら、この仕組みは丸ごと動かない（端末の中だけで動く）

置いているのはお題ごとのスコアだけで、個人を特定できるものは持たない。リポジトリが public なので
URL も置き場所の名前も誰でも見られるが、保存先は「今より高いスコアでしか上書きしない」ので、
いたずらされても記録が消えることはない。

### 保存先を用意する（初回だけ）

手元に Node を入れなくても、ブラウザだけでできる。

1. <https://dash.cloudflare.com> でアカウントを作る（無料）
2. **Storage & Databases → KV → Create a namespace**。名前は `BESTS` にする
3. **Compute (Workers) → Create → Start with Hello World → Deploy**。名前は `connect-plus-bests` にする
4. 作った Worker の **Edit code** を開き、中身を全部消して [`worker/index.js`](worker/index.js) を丸ごと貼り付けて **Deploy**
5. Worker の **Settings → Bindings → Add → KV namespace**。Variable name に `BESTS`、
   KV namespace に 2 で作ったものを選んで保存
6. Worker の URL（`https://connect-plus-bests.<サブドメイン>.workers.dev`）を
   [`src/app/sync-config.js`](src/app/sync-config.js) の `SYNC_URL` に貼って push

`wrangler.toml` も置いてあるので、手元に Node があるなら `npx wrangler deploy` でもよい。

動いているかは、ブラウザで `https://<Workerのurl>/bests/<SYNC_KEY>` を開くと分かる。
記録が JSON で見える（まだ何も預けていなければ `{}`）。

### 手元に控える方法も残してある

ホームの「記録の控え」から1行の文字列を書き出せる。保存先が使えないときや、
別のところへ移したいときのための出口。読み込みは今ある記録と高い方を採るので、戻して記録が下がることはない。

```
tashizan1:10=48,11=127,15=32
```

起動時に `navigator.storage.persist()` も頼んでいる。こちらは「しばらく遊ばないと消される」のを
防ぐためのもので、アプリを削除した場合には効かない。

## 更新の届き方

main に push すると1〜2分で Pages に出る。ホーム画面に追加したアプリは、**次に開いたときに新しい版が
裏でダウンロードされ、その次に開いたときから新しくなる**（起動を2回はさむ）。アプリを消して
入れ直す必要はない。消すと記録も消えるので、むしろ消さないこと。

## 構成

ロジックと表示を分けてある。`src/game/` は DOM も localStorage も触らないので、後でネイティブに作り直すときも中身を使い回せる。

```
src/game/config.js     お題・盤面サイズ・制限時間などの定数。数値を調整するならここ
src/game/rng.js        乱数（テストから固定シードを差し込めるようにしてある）
src/game/board.js      盤面、繋げられるセルの表、消去→落下→補充
src/game/solver.js     成立可能な組み合わせが存在するかの判定
src/game/generator.js  盤面の生成と、詰んだときの組み直し
src/game/game.js       1セッション。チェイン・スコア・時間
src/shared/bests.js    自己ベストの値そのものの扱い（アプリと保存先の両方から使う）
src/app/storage.js     端末への保存（自己ベストと設定）
src/app/sync.js        保存先とのやりとり。通信できなくても遊べる
src/app/sync-config.js 保存先の URL。空なら端末の中だけで動く
src/app/board-view.js  盤面の描画となぞり操作
src/app/main.js        ホーム / プレイ / 結果の画面遷移
```

## 実装で決めたこと

仕様に書かれていないぶんの判断。

- **消えるのは指を離したとき**。合計がぴったり一致してもその場では消さない。なぞっている途中で
  たまたま一致したときに、戻って別の繋ぎ方に変える余地を残すため。一致している間は盤面の下の
  合計の色が変わる
- **なぞりの間を補間する**。指を速く動かしても、前回位置からの線分を刻んで通過したセルを拾う。
  速さで結果が変わらないようにするため
- **繋げられるのはまわりの8マスだけ**。斜め2マス（間のセルを飛び越える）は、指でなぞる操作として
  直感に反するので廃止した
- **なぞっている最中に反応する範囲は、セルに内接する円**。四隅は反応しない。斜めのセルへ繋ぐとき、
  線が少し膨らむと上下左右のセルの角をかすめてしまうので、四隅を空けて通り抜けられるようにしている。
  円の直径はセル幅の9割強で、44pt は確保している。
  なぞり始めだけはセル全体で受ける（押さえた場所が反応しないのは分かりにくいため）
- **描画は3層**（下からタイル → チェインの線 → 数字）。線をタイルの上に描き、数字は線の上に
  来るので、線が数字を隠さない
- **詰み判定は探索を打ち切ったら「詰み」扱い**。遊べる盤面をたまに組み直してしまうことはあっても、
  詰んだ盤面を見逃すよりは害が小さい
- **テーマの切り替えをホームに置いた**。仕様の Settings に theme があるのに変える場所が無かったため。
  小さな文字ボタン1つに留めてある

## テスト

```sh
npm test
```

詰み判定（`solver.js`）は 3x3 盤面で総当たりと突き合わせて検証している。他は盤面の落下・補充、
チェインのルール、自己ベストの保存。

## 未決事項（spec 8章）の状況

3つとも実際に遊んで確定させた。

1. **お題の候補** — 10〜25 の1刻み（16通り）にした
2. **盤面サイズ** — 5×6 は窮屈だったので 4列×5行 にした
3. **数字の出現分布** — 等確率のまま。繋げられるのを8マスに絞ったうえで、実際に遊び進めた
   盤面（消して補充するのを繰り返した状態）を測ったところ、成立する組み合わせは中央値で
   お題10なら21通り、お題25なら500通り以上あった。詰みによる組み直しは1000回消して7回（お題10）、
   お題12以上では0回。小さいお題ほど、小さい数字が消えて大きい数字が残るぶん苦しくなる
